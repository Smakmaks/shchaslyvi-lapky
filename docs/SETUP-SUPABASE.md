# Підключення сервера (Supabase) для кабінетів клієнта й менеджера

Поки сервер не підключено, кабінет клієнта (`cabinet.html`) працює лише в браузері клієнта, а панель менеджера (`manager.html`) показує «Підключіть сервер».
Налаштування займає ~20 хвилин і робиться один раз.

---

## 1. Створіть проєкт Supabase (безкоштовно)

1. Зареєструйтесь на [supabase.com](https://supabase.com) (можна через GitHub).
2. **New project** → назва `shchaslyvi-lapky`, регіон **Central EU (Frankfurt)**, придумайте пароль бази (збережіть його, але на сайт він не потрібен).
3. Зачекайте 1–2 хвилини, поки проєкт створиться.

## 2. Створіть таблиці

1. Ліве меню → **SQL Editor** → **New query**.
2. Відкрийте файл [`supabase/schema.sql`](../supabase/schema.sql), скопіюйте **весь** текст, вставте → **Run**.
   Має з'явитися «Success. No rows returned». Файл можна запускати повторно (наприклад, після оновлень), дані не зітруться.
3. Там же виконайте окремий запит — зробіть себе адміністратором (вкажіть **свою** пошту, маленькими літерами):

   ```sql
   insert into public.staff (email, name, role) values ('ваша@пошта.com', 'Ваше ім''я', 'admin');
   ```

## 3. Увімкніть вхід за кодом на email

1. **Authentication → Sign In / Providers → Email**: має бути увімкнено (за замовчуванням так).
   «Confirm email» можна лишити увімкненим.
2. **Authentication → Emails → Templates → Magic Link** — замініть текст листа, щоб у ньому був **код**:

   ```html
   <h2>Код для входу в кабінет «Щасливі лапки»</h2>
   <p>Ваш код: <strong style="font-size:24px;letter-spacing:4px">{{ .Token }}</strong></p>
   <p>Або просто натисніть: <a href="{{ .ConfirmationURL }}">увійти в кабінет</a></p>
   <p>Якщо ви не запитували вхід — проігноруйте цей лист.</p>
   ```

   Тему листа можна змінити на «Код для входу — Щасливі лапки».
   Те саме вставте в шаблон **Confirm signup** (його отримують нові клієнти при першому вході).
3. **Authentication → URL Configuration**:
   - **Site URL**: адреса сайту, напр. `https://smakmaks.github.io/shchaslyvi-lapky/cabinet.html`
   - **Redirect URLs**: додайте `https://smakmaks.github.io/shchaslyvi-lapky/**` (і ваш домен, якщо є).

> ⚠️ **Ліміт листів.** Вбудована пошта Supabase надсилає лише кілька листів на годину — для тесту вистачить, для реальних клієнтів ні.
> Підключіть безкоштовний SMTP (наприклад, [Brevo](https://www.brevo.com) — 300 листів/день, або [Resend](https://resend.com)):
> **Authentication → Emails → SMTP Settings** → Enable custom SMTP → вставте дані SMTP від сервісу.

## 4. Впишіть ключі в `config.js`

1. **Project Settings → API** (або **Data API**):
   - **Project URL** → `https://xxxxxxxx.supabase.co`
   - **anon / publishable key** → довгий ключ, що починається з `eyJ…` або `sb_publishable_…`
2. У `config.js`:

   ```js
   backend: {
     supabaseUrl: "https://xxxxxxxx.supabase.co",
     supabaseAnonKey: "eyJhbGciOi…"
   },
   ```

3. Закомітьте й запуште — GitHub Pages оновить сайт за кілька хвилин.

> Цей ключ **публічний** — його бачить кожен відвідувач, і це нормально: доступ до даних обмежують правила в базі
> (клієнт бачить лише своє, менеджер — усе). **Ніколи** не вставляйте на сайт ключ `service_role` / `secret`.

## 5. Сповіщення в Telegram

1. Відкрийте `manager.html`, увійдіть своєю поштою → вкладка **⚙️ Команда**.
2. **Токен бота** — візьміть від @BotFather (можна того самого бота, що публікує пости в канал).
3. Кожен менеджер:
   - пише боту `/start` (інакше бот не має права йому писати);
   - дізнається свій chat ID у @userinfobot;
   - адміністратор вписує цей ID у таблицю «Команда» → 💾.
4. Або додайте бота в спільну групу менеджерів і вкажіть ID групи (починається з `-100…`).
5. Натисніть **📨 Надіслати тестове**.

Сповіщення в Telegram надсилає сама база (розширення `pg_net`, у Supabase воно є).
Якщо тест не приходить: **Database → Extensions** → переконайтесь, що `pg_net` увімкнено, і ще раз запустіть `schema.sql`.

## 6. Додайте менеджерів

**⚙️ Команда → Додати менеджера** → email + ім'я. Людина відкриває `…/manager.html`, вводить цю пошту та код із листа.
Роль «Адміністратор» додатково керує командою та налаштуваннями. Забрати доступ — 🗑 або зняти «Активний».

## Що отримує менеджер

| Подія | Сповіщення в панелі | Telegram |
|-------|:---:|:---:|
| Новий клієнт у кабінеті | ✅ | ✅ |
| Новий / змінений / видалений улюбленець | ✅ | ✅ |
| Нова автодоставка, пауза, пропуск, перенесення, зміна, скасування | ✅ | ✅ (із товарами, датою й адресою) |
| Замовлення з сайту від клієнта, що увійшов у кабінет | ✅ | ✅ |
| Дії інших менеджерів | ✅ (одразу «опрацьовано») | — |

У панелі нові події з'являються миттєво (Supabase Realtime) + раз на хвилину резервне оновлення; є звук, лічильник у вкладці браузера та сповіщення ОС (кнопка «🔔 Сповіщення в браузері»).

## Де дивитись дані напряму

**Table Editor** у Supabase: `profiles` (клієнти), `pets`, `subscriptions`, `orders`, `events` (журнал сповіщень), `staff`, `staff_notes`.
> На безкоштовному тарифі проєкт Supabase «засинає», якщо тиждень до нього не було жодного запиту
> (прокидається кнопкою в панелі Supabase). Поки магазином користуються щодня — це не проблема.

Резервні копії: на безкоштовному тарифі — **Database → Backups** (щоденні, 7 днів) або вивантаження таблиць у CSV.
